# 细纲写作组件

**Trigger**: "写细纲"/"写章节细纲"/"规划章节"/"细纲"

**核心理念**: 半自动。用户提供细纲核心内容（人物、事件、情绪冲突），AI读取设定辅助检查，生成提示词。AI不编造细纲内容。

---

## 硬规则

1. **禁止AI编造细纲内容**：出场人物、事件、冲突、情绪走向必须由用户提供
2. **等用户提供后再操作**：AI先问"请提供本章细纲"，等用户回复后再读取设定和检查
3. **AI只做辅助检查和格式化**：伏笔检查、连续性检查、生成提示词
4. **AI可以建议补充**：如"你可能需要考虑回收伏笔F001"，但必须等用户确认

---

## 前置条件

- 已运行组件一（项目设定），存在项目根目录
- 检测：`{project_root}/设定/世界观.md` 和 `{project_root}/角色/` 存在
- 未满足：提示用户先运行组件一

---

## 输入

- 项目根目录路径
- 用户提供的章节核心内容：
  - 出场人物
  - 事件/冲突
  - 情绪走向
- 项目已有的设定、角色、大纲、记忆账本

---

## 输出产物

1. **章节细纲**：`{project_root}/章节细纲/第XXX章.md`
2. **细纲提示词**：内嵌在细纲文件中，供正文生成使用
3. **正文提示词**：内嵌在细纲文件中，供正文生成使用

---

## 执行流程

### Step 1：用户写细纲核心内容

用户直接提供本章的核心内容，包括：

| 项目 | 说明 | 示例 |
|------|------|------|
| **出场人物** | 本章出场的角色 | 林风、黑衣人、林父 |
| **事件/冲突** | 本章发生什么事 | 林家被灭门，林风被重伤 |
| **情绪走向** | 情绪如何变化 | 平静→恐惧→绝望→愤怒 |
| **场景地点** | 在哪里发生 | 林家大宅→密室→废墟 |
| **关键动作** | 必须发生的动作 | 林风冲出密室、被黑衣人重伤 |

**用户输入方式**：
- 直接口述/文字描述
- 或按 `templates/细纲用户输入模板.md` 填写

### Step 2：AI读取前置内容并辅助检查

AI自动读取以下内容，辅助检查用户细纲：

#### 2.1 读取设定

| 读取内容 | 路径 | 检查目的 |
|---------|------|---------|
| 世界观 | `{project_root}/设定/世界观.md` | 确保事件符合世界规则 |
| 修炼体系 | `{project_root}/设定/修炼体系.md` | 确保修为/能力设定一致 |
| 金手指 | `{project_root}/设定/金手指.md` | 确保金手指使用合理 |
| 地图 | `{project_root}/设定/地图与世界.md` | 确保地点和距离合理 |
| 势力 | `{project_root}/设定/势力.md` | 确保势力关系正确 |

#### 2.2 读取角色状态

| 读取内容 | 路径 | 检查目的 |
|---------|------|---------|
| 角色卡 | `{project_root}/角色/*.md` | 确保角色行为不OOC |
| 角色状态追踪 | `{project_root}/记忆账本/角色状态追踪.md` | 确保状态连续 |

#### 2.3 读取大纲和前文

| 读取内容 | 路径 | 检查目的 |
|---------|------|---------|
| 总纲 | `{project_root}/大纲/总纲.md` | 确保不偏离主线 |
| 分卷细纲 | `{project_root}/大纲/分卷细纲/第X卷.md` | 确保符合卷内规划 |
| 上一章细纲 | `{project_root}/章节细纲/第XXX章.md` | 确保衔接 |
| 短期记忆 | `{project_root}/记忆账本/短期记忆.md` | 了解当前状态 |

#### 2.4 伏笔检查

1. 读取 `{project_root}/记忆账本/伏笔追踪.md`
2. 查询活跃伏笔（PLANTED + OVERDUE）
3. 检查用户细纲中是否需要回收/埋设伏笔
4. 输出伏笔提醒

#### 2.5 连续性检查

检查7个连续性变量与用户细纲是否矛盾：
- 金钱/资源、物品/装备、时间、位置、已知信息、能力状态、人际关系

#### 2.6 套路推荐（可选）

如存在 `{project_root}/拆文分析/套路库/`：
1. 根据章节位置和情绪基调匹配套路
2. 推荐Top 3套路供用户选择
3. 用户选择后注入细纲

### Step 3：生成完整细纲

AI基于用户核心内容 + 辅助检查结果，生成完整细纲：

- 调用模板：`templates/章节细纲模板.md`
- 输出位置：`{project_root}/章节细纲/第XXX章.md`

细纲包含：
1. 基础信息（章节号/标题/字数/核心看点）
2. 场景规划（2-3个场景，含地点/时间/角色/动作推进/五感/情绪）
3. 角色状态检查
4. 连续性检查
5. 伏笔安排
6. 写作要点（必须兑现/必须避免/风格要求）

### Step 4：生成提示词

基于完整细纲，生成两个提示词：

#### 4.1 细纲提示词

用于让AI理解本章细纲的完整上下文，格式：

```
## 细纲提示词

【世界观】{核心规则摘要}
【修炼体系】{当前等级和限制}
【金手指】{当前状态和可用功能}
【出场角色】{角色名：当前状态/OOC红线}
【活跃伏笔】{需回收/可埋设的伏笔}
【本章核心】{事件/冲突/情绪走向}
【场景规划】{场景列表}
【连续性约束】{7个变量的当前值}
【风格要求】{反AI风格+本书专属指南}
```

#### 4.2 正文提示词

用于正文生成的精简提示词，格式：

```
## 正文提示词

写第{X}章：{标题}
场景：{场景1}→{场景2}
角色：{角色列表及状态}
核心事件：{一句话}
情绪曲线：{起点}→{终点}
必须兑现：{要点列表}
必须避免：{禁忌列表}
字数：{目标字数}
风格：短句为主，动作化，口语化，硬截断结尾
```

### Step 5：用户确认

调用 AskUserQuestion 让用户确认：

**正确格式示例**：
```json
{
  "question": "细纲内容是否满意？",
  "header": "确认细纲",
  "options": [
    {"label": "满意，保存细纲", "description": "继续生成正文"},
    {"label": "需要调整", "description": "修改后再确认"}
  ],
  "multiSelect": false
}
```

**关键规则**：
- **label**：显示在选项标题栏，简短明确，是用户点击的目标
- **description**：显示在选项下方，仅作补充说明
- 不要把重要内容只放在description里

确认项：
- 细纲内容是否满意
- 提示词是否需要调整
- 确认后保存细纲文件

## 核心规则

1. 用户主导细纲内容，AI辅助检查和补充
2. AI必须读取所有相关设定后才给出辅助建议
3. 伏笔检查是必做项，不能跳过
4. 连续性检查是必做项，不能跳过
5. 提示词必须包含完整的上下文信息
6. 细纲确认后才能进入正文生成
7. 用户可以随时修改细纲，修改后重新生成提示词
