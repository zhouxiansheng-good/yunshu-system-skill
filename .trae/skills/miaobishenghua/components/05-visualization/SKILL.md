# 可视化拓扑组件

**Trigger**: "打开可视化"/"拓扑图"/"叙事宇宙"/"可视化编辑"/"启动可视化"

---

## 前置条件

- 已运行组件一（项目设定），存在项目根目录
- 未满足：提示用户先运行组件一

---

## 组件开关

项目级开关：`{project_root}/可视化配置.json`

```json
{
  "enabled": true,
  "auto_sync": true,
  "sync_interval_ms": 500,
  "server_port": 3456,
  "worldview": "default"
}
```

---

## 三层架构

### L1: 大纲宇宙

三个模块通过顶部标签切换：

#### 人物模块
| 属性 | 说明 | 对应文档 |
|------|------|---------|
| 节点 | 人物角色 | `角色/*.md` |
| 连线 | 人物间关系 | 事件过程+关系变化 |
| 关系类型 | 中立/友好/敌对/师徒/恋人/亲人/同盟/竞争 | 连线属性 |
| 章节范围 | 关系从第几章到第几章 | 连线属性 |

#### 金手指模块
| 属性 | 说明 | 对应文档 |
|------|------|---------|
| 节点 | 金手指/能力 | `设定/金手指.md` |
| 章节范围 | 从第几章到第几章 | 节点属性 |
| 成长描述 | 金手指的变化描述 | 节点属性 |

#### 势力模块
| 属性 | 说明 | 对应文档 |
|------|------|---------|
| 节点 | 势力/组织 | `设定/势力.md` |
| 势力类型 | 门派/组织/国家等 | 节点属性 |
| 连线 | 势力间关系 | 事件过程+关系变化 |

### L2: 细纲星系

四个模块：人物/金手指/势力/章节

- 继承L1层数据
- 显示本章出场人物、状态变化
- 显示章节节点、场景分解、伏笔安排

### L3: 正文星尘

双面板设计：
- 左侧：正文编辑区
- 右侧：词汇替换参考

## 执行流程

### Step 1：前置检测

1. 检查项目是否已初始化
2. 读取 `{project_root}/可视化配置.json`
3. 若未启用，询问用户是否启用

### Step 2：扫描项目文档生成三层节点

**L1 扫描**：
- `角色/` → 人物模块节点
- `设定/金手指.md` → 金手指模块节点
- `设定/势力.md` → 势力模块节点

**L2 扫描**：
- `章节细纲/第XXX章.md` → 章节节点
- 继承L1数据创建变化记录

**L3 扫描**：
- `正文/` → 正文章节节点

### Step 3：启动可视化服务

```bash
cd {skill_dir}/components/05-visualization/server
node server.js --project-root "{project_root}" --port {port}
```

### Step 4：用户可视化编辑

支持操作：
- 拖拽节点调整位置
- 拖拽连线建立关系
- 单击/双击/右键节点操作
- 按类型筛选显示
- 三层宇宙切换（快捷键 1/2/3）
- 模块切换（人物/金手指/势力）

### Step 5：双向同步

**网页→文档**：WebSocket发送更新，服务端保存到拓扑数据文件
**文档→网页**：chokidar监听文件变化，自动更新节点

## 关联组件

- 组件一（设定）：创建项目骨架和可视化配置模板
- 组件二（拆文）：提供词汇库、句式库
- 组件三（细纲）：章节细纲→生成L2节点
- 组件四（正文）：正文写作→生成L3节点

---

## 核心规则

1. 三层独立，每层有自己的节点和边
2. L1三模块独立管理，通过标签切换
3. 粗粒度映射：一个节点对应一个文件或一个核心事件
4. 双向同步，500ms防抖
5. 自动归档，保留最近20个快照
